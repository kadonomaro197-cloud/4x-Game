Force Management — every unit you own, in one order of battle

This is the Force Management window (the class is still FleetWindow — renaming it would break every save) grown into what you asked for: one place that lists, details, and controls every unit you own — military and civilian, on the space side (ships and fleets) and the planet side (battalions and their individual units) — plus your holdings (colonies, stations). About 70% of this is already built: the window exists with a Fleets tree and a cross-body Battalions table sharing one order path. The missing 30% is the single unified roster, a working military-vs-civilian tag, and per-individual ground-unit rows. The one thing to understand first: the engine cannot tell a warship from a freighter today — the intended flag is dead code — so this window derives the answer from what's bolted on the hull, and that derivation must live engine-side so the AI reads the identical value. Every column, cell, and order below is graded by whether the code does it today, only holds the data, or is work to build.

⚑ The one thing the engine can't tell you: military vs civilian

You asked for "units both military and non-military." Here's the honest ground truth, and why the fix is an engine job before it's a window job.

The intended flag is dead code.

There is a ShipInfoDB.IsMilitary field (ShipInfoDB.cs:38) — and siblings Tanker, Collier, SupplyShip, Conscript. They're declared and copied when a ship is cloned, but never set and never read anywhere in the whole solution. Ship designs carry no role or category. Fleets carry no classification. On the ground, unit types are Infantry / Armour / Artillery only — all combat — and the design is deliberately locked against adding "civilian" unit types (a unit's role must emerge from what it carries, not a label).

So the window must derive the classification from components — never read a stored field. A ship with a weapon is a warship; strip its weapons and it stops being one. A ship with a logistics module is a freighter; a survey sensor makes it a survey ship; a troop bay makes it a transport. A ground unit with attack ≤ 0 is support.

And the derivation belongs in the engine, not the window — the studio law is one verb, both seats: if the AI can't read the same "is this a warship?" answer the player sees, you've built two truths. The recommendation from the survey: one small, tested engine helper — ShipRoleTools.ClassifyRole(ship) — that both the Force Management window and the faction AI call. The ground side already has one (GroundRoleComposer.ClassifyRole, GroundRoleComposer.cs:45) — it's just never shown to the player.
