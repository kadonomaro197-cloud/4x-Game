Pulsar4X · component designer · a PROPOSED new door — projected effects

Every other door changes the unit that carries it. This one changes the units around it.

An aura is the one capability that does not fit any door built so far. Weapons, Defense, Enhancers, Propulsion — all of them act on the unit that mounts them. A rally banner, a dread presence, a command net, a jamming bubble, a projected shield — each reaches OUTWARD, changing OTHER units inside a radius. That single difference — it acts on someone else — is why it earns its own door and cannot be an Enhancer.

🔑 The honest headline first, because it governs everything below: this door is mostly still a SPEC — but two of its five effects shipped in 2026-08, in a simpler shape than drawn here. The per-unit aura pass this door proposes — code that each tick walks a unit's neighbours, filters by friend-or-foe, and applies an effect by area — does not exist. What shipped instead is a scalar fold: Command lifts a whole fleet/battalion's firepower and Ward stiffens its toughness (one multiplier over the formation — FleetAuraMult / GroundCommandAura), the way a flagship buffs its group. The other three — Rally, Dread, Jamming — are unbuilt (Rally/Dread still want a morale field that does not exist, the wall the Steadiness / fury enhancer hit). So read the panel below as the richer per-unit shape the engine could still grow into; the two green rows mark what already plays, as a fold.

Why it is a door, not an Enhancer — the one-line test

The Enhancers door has a written thesis: "an enhancer is a scalar multiplier on a stat the unit already has." An aura fails that test on the word OTHER.

An Enhanceracts on SELF

Power armour raises this unit's carry. A reflex booster raises this unit's evasion. The number it writes lands on the sheet of the part's own host. You can set it knowing only the unit.

An Auraacts on OTHERS

A rally beacon raises the morale of every friendly unit within range. It writes nothing on its own host's combat sheet — its whole output is a field that lands on someone else. There is no "stat it already has" to multiply, because the target is not itself. That is a different verb, so it is a different door.

🔒 The intrinsic test still passes for the DIALS. How strong the field is, how far it reaches, and who it targets are all settable knowing only the projector component — so strength, radius and target are legitimate designer dials, not assembly decisions. What is not a dial is how many units it actually hits: that depends on who is standing in the radius when it fires, which is a battlefield fact, not a property of the part. So that number is an emergent readout, shown but never set.

The one engine primitive this whole door needs — the aura pass

Every effect above waits on the same missing piece. It is small, and it is one thing.

The aura pass, in plain terms: once per tick, for each unit that mounts an aura projector, walk the units near it, keep the ones whose IFF matches the projector's target choice and that fall inside the radius, and add (or subtract) the effect from a named variable on each. That is the entire mechanism — the same shape as a weapon's target-acquisition sweep the engine already runs, except it writes a buff instead of a hit. Nothing about it is exotic; it simply has not been built.

Two guard-rails the pass must respect, so the door does not become a "pretty" one:

1  Auras do not stack without limitthe balance rail

Two rally beacons over the same squad must not double the morale. Take the best single field of each kind, not the sum — the exact rule the Defense door already uses for shields-that-take-the-best. Otherwise a stack of cheap projectors becomes free invincibility, which is the "everything is free" failure this campaign exists to delete.

2  A destroyed projector drops its field instantlythe grave rung

The aura is a component. Kill the unit carrying the command uplink and every friendly unit that was quickened returns to its base speed that tick. That is what makes an aura projector a real target — a decapitation strike on the beacon-bearer is a genuine tactic, and the field is only as alive as the part that emits it.

Cradle to grave — the aura is a component, so it earns the whole chain

The reason to model an aura as a component rather than a bespoke engine flag: it inherits research-gating, construction-from-materials, save/load and the design UI for free — and it can be lost. Trace it end to end.

RungFor an aura projector
mineral → materialthe same mined + refined stock every component is built from — an emitter is metal and electronics, not magic
researcha tech gates what fields you can design and how strong — a faint short rally is early, a grand command net is late
componentthis door — pick the effect, the target, the strength and the radius; out comes a designed projector
build → installbuilt at a colony from materials, installed on a unit or a building like any other component
the decision (the lever)which unit carries the beacon, where it stands, whether the field is on — a positioning choice, because the field moves with its bearer
damaged / destroyedthe grave rung — the projector is a component that can be shot off; when it dies the field dies with it, that tick

🔒 No rung is skipped. An aura that were a bespoke engine flag — un-researchable, un-buildable, un-killable — would fail cradle-to-grave, the "pretty" disease in its vertical form. Modeled as a component, it is a thing you discover, build, place, and lose.

🔒 Five effects cover the field, one is deferred for a stated reason, one is refused for a stated reason. That is the bar: an effect earns a slot only if it writes a nameable variable and rides the component chain. A healing aura is deferred not because it is unwanted but because the state it would repair does not exist yet — the same wall, named so it is not lost.

Where the door stands

This is a proposed door, and it is honest about being a spec. It gives the projected-effect capability a real home — one forced choice (what it projects) + a target choice (friend / foe / all) + two dials (strength, radius) — and it passes the intrinsic test for every dial while keeping "how many it hits" as an emergent readout, never a knob.

⚠ Two of the five effects now reach the running game — Command and Ward, shipped 2026-08 as fleet/battalion scalar folds (firepower and toughness, one multiplier over the formation). The per-unit aura pass this door draws — walking a unit's neighbours and applying an effect by area — still does not exist, so the richer per-neighbour shapes remain a spec. The other three write a variable that is not there: Rally and Dread need a morale field (the wall the Steadiness / fury enhancer hit), and Jamming was shelved for v1 even though its target variable — detection range — is real.

What is left to build: ① the per-unit aura pass + Jamming (wires straight into sensors / fog-of-war — the variable already exists); ② the per-neighbour, by-area versions of Command and Ward, if the richer shape is ever wanted over the shipped fold; ③ Rally and Dread (build the morale field once and these light up alongside the fury enhancer). Two guard-rails stay non-negotiable for any aura pass: take-the-best not sum (no free stacking) and a destroyed projector drops its field that tick (the grave rung that makes the beacon-bearer a target).
