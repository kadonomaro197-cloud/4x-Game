Pulsar4X · the ENTITY ASSEMBLER · the second half of the design pair

The twelve doors make parts. This is the machine that turns a pile of parts into a ship.

Every door-designer stamps out a component — a gun, a reactor, a suit of armour. But the combat resolver never reads a gun; it reads one Firepower number for the whole ship. It never reads a plate; it reads one Toughness number. The Entity Assembler is the machine in the middle: you pick a host (a hull, a ground frame, a station), bolt on your designed components — and how many of each — and it adds them up into the handful of totals the fight actually runs on.

🔑 The one rule that defines this door: it only owns the decisions you cannot make knowing a single part. How much a gun hurts is the Weapon door's dial — you set it knowing only the gun. How many guns, on what hull, next to what reactor — those need the whole entity in front of you, so they live here. And a third kind of number — Firepower, Evasion, effective health — belongs to nobody's dial: it only exists once everything is assembled. The Assembler is where those get computed, never set.

Three kinds of number — and this door owns exactly one of them

The boundary is the whole design. It comes straight from the intrinsic test in DESIGNER-NORTH-STAR.md: can you set this knowing only the part in your hand?

A component DIALlives in a door, not here

Set knowing only the part: a weapon's damage, a plate's thickness, a reactor's output. The Assembler reads these off the components you mounted and never re-sells them — it shows them greyed, marked read.

An ASSEMBLY decisionTHIS door's dials

Needs the whole entity in front of you: which host, which components, how many of each, and — for a ground design — how many models the unit fields. You cannot set any of these knowing one part, so they are the Assembler's own controls.

An EMERGENT readoutcomputed, never set

Only exists once the whole thing is built: Firepower, Toughness, Evasion, effective health, detection footprint. Nobody's dial. The Assembler computes them from everything mounted and hands them to the resolver, marked emergent.

🔑 Because the totals are host-agnostic, so is the Assembler. A ship, a ground unit, and a station all produce the same totals bundle — Firepower, Toughness, Evasion, Shield, weapon profiles, cost. Only the host choice, the gates that apply, and the model-count differ. That is the combat north star — "ground units work the same as ships as far as fleets or battalions are concerned" — made concrete: one assembler, both seats, one primitive the AI and the player both drive.

Cradle to grave — the Assembler is where the chain becomes a thing you can lose

Every component reached here by the full chain (mineral → material → research → designed in a door → built at a colony). The Assembler adds the two rungs a single door cannot: the entity the components add up to, and the loss when it dies.

damaged / destroyedwhole-or-dead today — the entity rates at full value until it is removed. Per-component damage (DamageComplex) is parked; the grave rung is coarse until it lands.
The honest limit, stated plainly. The engine is whole-or-dead: a ship or unit is at full strength until the instant it is destroyed, and combat value is cached at build and never recut on damage. So the Assembler's totals are a build-time nameplate, not a live-under-load reading. Everything that would make a fielded entity wear, degrade, or lose one model at a time waits on the same parked per-component-damage model — flagged here, never faked.

Where the Assembler stands

This is the design the in-game assembler will mirror. Its shape is settled: one host choice, a component × count roster (separate weapon profiles, never blended), a model-count dial, the live budgets and gates (mass/carry, power supply vs draw, crew, ammo), the emergent totals (Firepower/Toughness/Evasion/Shield), and the cost surface summed in one place — then the totals handoff to the resolver.

🔒 The boundary held. Every dial here passes the intrinsic test at assembly time and NOWHERE else: you cannot set "how many guns on what hull" knowing a single gun. Component dials are read, never re-sold; combat totals are computed, never set. That line is what keeps the Component Designer and the Entity Assembler from fighting over the same number.

⚠ What it must flag, never fake (each designed, each waiting on one engine primitive): model count (the six-man squad — no per-model count in GroundUnit yet), per-component damage (whole-or-dead; the grave rung is coarse), and the pending door outputs it carries through — the morale field (fury/rally/dread), the aura pass, the colonist unload path, and the strike-craft launch caller. The wiring is designed now so that when each primitive lands, the number already has a home.
