# 01-IO-COMMAND — Command, re-derived - one seat built twice, and the 26-leader grid it should be
> Source: `docs/Actual HTMLs Of designers/commandderived.html` · Component-designer door · Census (Phase 1 draft, unverified)

## What this door builds
This door designs a **command seat** — the component you install to give a post a commander. In the running game today it is actually **three** separate components that all do the same job at different sizes: an **administrative complex** (`admin-complex`, sizes a colony's buildable hex map), a **ship bridge** (`ship-command`, whose `Console Space` dial is read by nothing), and the newer **Command Berth** (`CommandBerthAtb`, the best-built one — it has Role, Grade, Support, Survivability, and a hazard roll that can kill the seated officer). The point every one of them makes to the simulation is the same: *what this post commands, how well, and whether the person in it survives the job.*

The HTML then argues these three are two halves of one grid and shows an **interactive PROPOSAL builder** that collapses them into **one** component chosen by two forced choices — **Scope × Domain** — plus three "how much seat" sliders (Grade, Support, Survivability). Pick a scope (Field / Planet / System / Empire) and a domain (Space military … Governor) and the panel names the leader role you just built, the one decision that role owns, and what it costs. The builder that is wired in this file is that **proposal**, not the as-built designer — its own banner states *"None of this exists in the engine yet."*

## D. NOTES / DISCREPANCIES

**This HTML's live builder is the PROPOSAL, not the as-built designer.** The interactive panel (`p_*` ids, Scope×Domain + Grade/Support/Survivability) is explicitly *"what we intend the door to become"* (`.whichb.prop` banner) and *"None of this exists in the engine yet."* Its outputs are therefore **engine-pending** except the leader-hazard roll, which rides the one live mechanic (`SiteHazard`). The as-built door — the thing a player can actually open today — is described only in the prose bands and its dials are **not** interactive here. Those as-built dials are:

- **`Admin Level`** (`AdminSpaceAtb.AdminLevel`, 11-value ladder Ship→Empire): set from the template dial, copied into the seat's `SeatType` by `AdminSpaceProcessor.ReconcileSeats`, printed at `AdminWindow.cs:172` — and **read by no rule** (`AssignAdministratorOrder`/`UnassignAdministratorOrder` never look at level). A promise the UI shows and the rules do not keep. Free (in no cost formula).
- **`Office Space`** (admin-complex template, 10→10,000): `Mass = Office Space × 100`; drives `ColonyHexMapDB` via `hexMapDB.UpdateMaxRadius: radius = ceil(officeSpace/100)`, gated in `ColonyHexMapProcessor.ProcessEntity` on `ColonyInfoDB` + `AdminSpaceDB`. Costs Mass×100, crew×0.25, research×0.5. **Live** and honest (hexes-per-tonne falls as you scale → no dominant setting).
- **`Console Space`** (ship-command/bridge template, 1→20): same `AdminSpaceAtb`, same cost pattern (Mass×100, crew×0.25, research×0.5), but its only consumer is gated on `ColonyInfoDB`, **which a ship does not have — so it is read by nothing**. `ReconcileSeats` gives one seat per component keyed by *name* (`current.Add((atb.AdminLevel, adminSpace.Name))`), never consulting console count → a 1-console bridge (100 kg) and a 20-console bridge (2,000 kg) both give exactly one seat. **The minimum is strictly dominant; a dead cost dial.**
- **Command Berth dials** (`CommandBerthAtb`): `Role` (5 site roles, read by `GetWorkingBerth`, gates site type — a choice not a scale); `Grade` (1→10, read at `SiteWorkProcessor:279`, ×10 work rate, costs Mass×200/crew×2/research×10 — the only honestly-priced dial); `Support` (0→50, `SiteWorkProcessor:280`, +50% at top via `Grade×(1+skill+Support/100)`, **costs NOTHING**); `Survivability` (0→100, read by `SiteHazard`, buys down the leader-death roll, **100 zeroes it**, **costs NOTHING**); `Span` (1→10, documented *"the force size the berth can command (SE-3+)"*, **read by nothing, costs nothing**).

**Two dead-cost / free-immunity landmines the door itself flags:**
- **`Survivability` is free immunity that deletes the door's own grave rung.** `SiteHazard` is the only place in the designer where a named character can die from a decision; `Survivability` is absent from `Mass`, `Volume`, `CrewReq`, `ResearchCost`, `CreditCost`, `BuildPointCost`, `ResourceCost` — so every berth ever designed is set to 100 and immune. The proposal's fix: cost mass **and cap at 95**.
- **`Console Space` is a cost dial that writes nothing on the bridge** — same failure shape as the Sensors door's fire-control pair; the minimum setting is a free 20× saving.

**`ColonyHexMapDB` clone landmine (L12).** The admin-complex's only real output blob has **zero `Clone` references** — it is the live example named in the root `CLAUDE.md` landmine index. `BaseDataBlob.Clone` is virtual-with-garbage-default, so the blob silently becomes a bare `System.Object` when its entity is cloned between managers. Latent (colonies don't change system today), but the Site Engine's located-site work heads straight at it.

**Grid-count discrepancy.** The prose §"Does it reproduce the roster?" claims *"32 cells, 27 filled, 5 justified blanks"* (26 roster roles + Head of State), but the shipped `P_ROLES` JS object actually contains **21 filled cells**, and `buildGrid()` renders **21 seats / 11 deliberate blanks / 32 cells** into `#p_grid`. The three "new Field seats" (Yard Master, Convoy Master, Magistrate) and others described in prose are present in `P_ROLES`; the prose's 27 figure counts roster narrative rather than the live JS. Census reports the JS ground truth: 21 filled, 11 blank.

**Three rulings the door says are owed before build:** (1) does a ship's captain become a seat (makes a bridge component mandatory on every ship)? (2) Ambassador+Envoy — **RULED merged** (Grade is the stage); took the roster 21→20 before the three new Field seats took it to 23. (3) Is `AdminLevel` safe to collapse — it is a `[JsonProperty]` enum with **ordinal saved values**, so dropping the middle three rungs shifts every value above and breaks saves (landmine L3); needs explicit numbering or a converter.
